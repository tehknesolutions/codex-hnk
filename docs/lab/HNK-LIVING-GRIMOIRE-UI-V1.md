# HNK CODEX — Living Grimoire UI V1

## Visual direction — APPROVED

**The interface is not a dashboard decorated like a magic book. The interface is the Codex itself.**

The approved concept image from the 2026-09-20 design session is the principal visual reference for the first implementation pass.

### Experience
On desktop, the primary object is an open, richly materialized grimoire. Pages are real interaction surfaces. Navigation, diagrams, matrices, provenance and graph exploration belong to the book's physical/arcane language rather than floating generic SaaS cards.

### Canon boundary
The concept image establishes **art direction**, not automatic symbol canon. Generic arcane marks are placeholders. Production should progressively replace them with approved HNK glyphs, HENUVOKODAN and canonical iconography. Visual similarity never creates correspondence.

### Information translation
- 7 pillars → illuminated pillar wheel / initiatory diagram
- 49 domains → domain matrix and folios
- Knowledge Graph → constellation / engraved relational map
- Source corpus → library/manuscript layer
- Provenance → marginalia, seals and source drawer
- Maturity → inspectable layered indicators, never a single score
- Status → SOURCE_ASSERTED / HNK_CANDIDATE / HNK_APPROVED / UNRESOLVED

### Interaction
Page turn, glyph awakening, traced connections, matrix illumination and subtle depth can communicate navigation/state. Reduced-motion mode must preserve all information.

### Responsive rule
Desktop uses the iconic two-page spread. Mobile becomes a **single-page living folio** rather than shrinking the desktop book into an unreadable miniature.

### Product principle
**HNK CODEX = grimoire + knowledge graph + laboratory + computational artifact.**
