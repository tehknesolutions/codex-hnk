# HNK — Ecosystem Authority Map V1

**Status:** HNK_APPROVED_BY_TW
**Data:** 2026-09-29
**Escopo:** fronteiras de autoridade e integração entre CODEX-HNK, HNK-KODE, HNK-VERSE e TEHKNE-OS.

## 1. Hierarquia
HNK é o domínio máximo. CODEX-HNK é a autoridade integral de registro, cânone, contratos e integração do HNK. HNK-KODE é a autoridade linguística e computacional do HENUVOKODAN. HNK-VERSE é plataforma/metaverso consumidor de contratos. TEHKNE-OS é a autoridade sobre memória tecnológica, arqueologia, evidência e know-how da Tehkné Solutions; não é o metacentro do HNK.

## 2. Fluxo
CODEX-HNK -> fundamentos/contratos HNK -> TEHKNE-OS
TEHKNE-OS -> evidência tecnológica/know-how -> CODEX-HNK / TECNOLOGIA
CODEX-HNK -> contratos canônicos -> HNK-KODE / HNK-VERSE
HNK-KODE -> contratos linguísticos/computacionais -> consumidores HNK

O fluxo pode ser bidirecional, mas a autoridade não é simétrica.

## 3. Promoção
DADO/EVIDÊNCIA -> PROVENIÊNCIA -> INTERPRETAÇÃO -> CANDIDATO -> VALIDAÇÃO -> PROMOÇÃO CANÔNICA

Dado, experimento ou descoberta não se torna cânone apenas por existir ou passar em teste técnico. A promoção respeita a Constituição de Lucidez e preserva histórico, estado e proveniência.

## 4. Glyph Genesis
CODEX-HNK mantém laboratório estrutural/matemático e evidência. HNK-KODE decide o estado linguístico de glyphs, PATHs, lexemas e regras. PATH matematicamente válido != glyph linguístico canônico.

## 5. Operação
GitHub é o registro versionado. Decisões materiais não devem permanecer exclusivamente em chat. Fluxo preferencial: ChatGPT/Codex -> GitHub -> CI/validação remota -> produção. Local não é gate padrão.

## 6. Não duplicação
Cada objeto possui fonte de verdade primária. Consumidores preferem contratos, referências e proveniência a cópias integrais de árvores mantidas por outro repositório.
