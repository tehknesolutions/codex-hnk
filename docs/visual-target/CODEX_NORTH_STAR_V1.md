# CODEX-HNK — NORTH STAR VISUAL TARGET V1

Status: VISUAL_TARGET
Authority: approved by Creator (A.S.)
Master roadmap: #379

## Purpose
This document freezes the approved experience target for the CODEX-HNK interactive product. It is a product/UX contract, not a source of canonical HNK doctrine or data.

## Prime experience
The user must perceive that they have entered and opened a living CODEX/grimoire, not a conventional website or dashboard.

The book/artefact is the primary interaction surface. Navigation, maps, diagrams, knowledge, sources and practices belong to the same world and should feel embedded in the artefact.

## Visual invariants
1. Sacred editorial fantasy / monumental codex language.
2. Dark obsidian/metal environment with restrained gold framing.
3. Parchment/manuscript surfaces for knowledge-dense spreads.
4. High editorial density without sacrificing hierarchy or readability.
5. Sacred geometry and diagrams are functional navigation, not decoration alone.
6. Light/glow communicates hierarchy, state, selection or meaning; it is not indiscriminate neon.
7. The central viewport is the Codex itself.
8. Navigation rails must feel physically/internally connected to the Codex.
9. Desktop should feel monumental; mobile must preserve the Codex metaphor rather than merely stack desktop cards.
10. Macro → micro navigation should remain spatially and conceptually coherent.

## Functional target
The mature product supports traversal through:

Pillar → Domain → Matrix cell → Concept → Relation → Source → Practice

and also provides direct paths through Journey/Days, Tree HNK, Library, Labs, HENUVOKODAN and global search.

## Content authority classes

## Non-goals
- Do not recreate the target as one giant static image.
- Do not reduce the target to a themed dashboard.
- Do not promote AI-generated labels/counts from visual references into HNK canon.
- Do not block delivery on a local workstation environment.
- Do not spend major cycles polishing an isolated landing page while the Living Book architecture is absent.

## M1 acceptance contract
When any principal area opens, the primary perception must be “I am inside the CODEX.”

The persistent shell must provide:
- CodexTopbar
- CodexNavRail
- CodexViewport
- CodexContextRail
- coherent responsive/mobile adaptation

Existing routes/content should remain reachable during migration. M1 prepares the central viewport for M2 Living Book Engine.

## Operational pipeline
ChatGPT/Codex → GitHub → remote CI/preview → production.

Local execution may be useful but is not a project gate.

## Definition of visual convergence
Convergence is not achieved merely because screenshots resemble the target. It is achieved when the visual language, spatial model and interactions consistently make the product behave like the living Codex represented by the North Star.
